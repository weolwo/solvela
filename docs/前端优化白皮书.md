# 前端优化白皮书 · 产物 26 MB → 8.3 MB

> 分支：`upgrade/springboot4`
> 日期：2026-08-02
> 范围：`smart-admin-web-javascript/`
> 配套：后端见 `docs/后端升级白皮书-SpringBoot4.md`

## 0. 一句话结论

构建产物从 **26 MB 降到 8.3 MB（-68%）**，主要靠三件事：
**① 把 monaco-editor 换成 CodeMirror 6**（-11 MB，占全部收益的 8 成）、
**② 两个"全量引入"改成按需**（highlight.js、echarts）、
**③ 卸掉从未生效的依赖**（v-viewer、整条 eslint/stylelint 链）。

过程中顺带修掉 **3 个静默失效的 bug** —— 它们的共同点是**不报错**，只是功能悄悄不工作。

## 2. 按需引入

### 2.1 highlight.js：943 KB → 36 KB

代码生成器预览用的是 `import hljs from 'highlight.js'` —— **默认入口会把全部约 190 种语言打进产物**，
而实际只注册 java / javascript。改成官方推荐的 `highlight.js/lib/core` + 按需 `registerLanguage`。

gzip 从 300.27 KB 降到 **11.31 KB**。

> 🐛 顺带修掉一个 bug：原来是
> `registerLanguage(language, language == 'java' ? java : javascript)`，
> 于是导入的 `typescript` 语法**从来没被注册过**，TS 一直在用 JS 语法高亮。改成按 key 取的映射表。

### 2.2 echarts：1112 KB → 573 KB

`import * as echarts from 'echarts'` 改为 `echarts/core` + 按需 `use()`，
新增 `src/lib/echarts.js` 统一注册，四个图表组件共用。

实际只用到 4 种 series（bar / line / pie / gauge）与 4 个组件（grid / legend / title / tooltip），
外加 `graphic.LinearGradient`（在 core 里）。

> ⚠️ **按需引入漏注册是"空白图表且控制台不报错"**，没有任何显式信号。
> 所以做了实测：临时挂 dev 路由把四个图表挂上，用 canvas 像素采样确认都有真实内容
> （非透明采样 147~733、色彩数 25~80；空白图表应为 0/1），控制台零告警。

## 3. monaco-editor → CodeMirror 6

### 3.1 先走过一段弯路（记录下来避免重走）

最初的思路是"把 monaco 精简"，做了两轮：

1. **删 `public/vs` 里用不到的文件**：用浏览器网络面板实测出真正被请求的 17 个文件，
   据此删掉 94 个（80 个用不到的语言定义、12 个非中文 NLS 语言包、css/html worker），14.98 → 11.49 MB。
2. **改用 ESM 打包**（`loader.config({ monaco })` + Vite 原生 `?worker`）：
   构建成功，但产物**反而从 19.4 MB 涨到 25 MB** ——
   `editor.main` 会连带引入 css/html 语言服务，把两个 worker（2.25 MB）又拉了回来；
   而且 ESM 的 `ts.worker` 是 8.1 MB，比预构建版的 6.69 MB 还大。

**结论：ESM 迁移不能减小体积**，它的价值只有仓库卫生。这两轮最后都被 §3.2 取代。

> ⚠️ **`vite-plugin-monaco-editor` 在 monaco 0.56 上用不了**（含维护分支 `-esm`）。
> 它硬编码 `monaco-editor/esm/vs/...` 路径，而 0.56 的 exports 映射是 `"./*": "./esm/vs/*.js"`，
> 这类路径会被解析成 `esm/vs/esm/vs/...js` 而报
> `Rolldown failed to resolve import`。正确写法是去掉 `esm/vs` 前缀。

### 3.2 最终方案：换掉

真正的问题是**需求错配**：这套编辑器的实际用途是"浏览器里看代码 + 偶尔改一改"，
脚本主要在 IDEA 里写、用 git 管。为此付 monaco 的 11.5 MB 不划算 ——
其中 `ts.worker` 一个就 6.7 MB，**只为 JS 智能提示**，而那个入口还因为大小写 bug 从未真正生效过（见 §4.3）。

| | monaco | CodeMirror 6 |
|---|---|---|
| 产物 | 11.49 MB | **444 KB**（gzip 148 KB） |
| node_modules | 98 MB | 4 MB |
| 仓库 committed 二进制 | 11.5 MB | 0 |

**新增的三个文件**：

| 文件 | 职责 |
|---|---|
| `src/lib/codemirror.js` | 语言装配（java / json）、字典补全源、基础扩展集 |
| `src/components/business/code-editor/SmartCodeEditor.vue` | 编辑器组件，prop 与原 `vue-monaco-editor` 保持一致（`v-model:value` / `language` / `theme` / `height`），调用方几乎不用改 |
| `src/components/business/code-editor/SmartCodeDiff.vue` | 左右分栏 diff（`@codemirror/merge`） |

**语言收口为 java / json 两种。**
QLExpress 脚本用 `java` 高亮 —— QLExpress 4 的语法已是 Java 风格（含原生 JSON 字面量），
比原先自制的关键字 tokenizer 准得多，那个 tokenizer 已删除。

> ⚠️ **编辑器只做着色，不做语法检查。**
> QL 的语法校验要走后端已有的 `check(script)` AST 预校验接口，前端拿错误位置再划红线 —— 那是独立的事。

**三处行为差异（需知悉）**：

1. **格式化降级**：CodeMirror 没有通用 formatter。JSON 用原生 `JSON.stringify` 重排；
   java 无格式化器，改成**明确提示**而不是点了没反应。
2. **JS/TS 智能提示没有了** —— 这正是 `ts.worker` 那 6.7 MB 的用途。语法高亮不受影响。
3. **只读观感**：CodeMirror 的 `EditorState.readOnly` 只拦修改、不改 `contenteditable`，
   实测发现光标还在、看着像能编辑，已叠加 `EditorView.editable` 补齐。

### 3.3 语言选择入口在哪

| 页面 | 语言切换 | 说明 |
|---|---|---|
| 在线编辑器（`/code-editor`） | 工具栏下拉 | `SmartRuleEditor` 自带工具栏（暂存 / 提交 / 格式化 / 语言 / 主题 / 窗口大小 / 只读） |
| 任务模板设计器 | 两个面板右上角各一个下拉 | 两个编辑器分别默认 java（rule_script）与 json（ui_schema） |

> 曾经一度按"不要语言切换"的要求把下拉整个移除，后又按澄清后的需求加回。
> `SmartCodeEditor` 组件本身**不含**工具栏，语言由调用方通过 `language` prop 决定。

## 4. 修掉的静默失效 bug

这三个的共同点：**不报错、不崩溃，只是功能悄悄不工作**，不专门去看根本发现不了。

### 4.1 前端 lint 整条链是死的

`package.json` 里装着 eslint 10 + 一整套插件，但：
- 配置文件是 eslintrc 格式的 `.eslintrc.cjs`，而 **ESLint 9 起不再认**，实跑直接报
  `couldn't find an eslint.config.js`；
- stylelint 的配置 `extends` 了**根本没装**的 `stylelint-config-prettier`（stylelint 15 起已废弃移除）；
- 而且 `package.json` 里**从来没有 lint 脚本** —— 两套配置从未被执行过。

已整条卸载（npm 实际移除 192 个包），保留 prettier（IDE 保存时格式化在用）。

> 要恢复得写 `eslint.config.js` flat config + 摘掉 `stylelint-config-prettier` + 补 lint 脚本，
> **不要只把包装回来**，那样仍然跑不起来。

### 4.2 v-viewer 零引用

全项目搜不到 `v-viewer` / `VueViewer` / 相关指令，既没注册插件也没用过。已卸载。

### 4.3 monaco 语言 id 大小写导致高亮静默失效

`SmartRuleEditor` 的语言下拉 value 写的是 `['QL', 'JSON', 'Javascript']`，
而 monaco 注册的是小写 `json` / `javascript` —— **语言 id 大小写敏感**。
实测 `createModel('JSON')` 解析结果是 **`plaintext`**：选中这两项时既没有高亮、也不报任何错。

修法是 label / value 分离（显示名不变，value 用正确的 id）。

> **通则**：凡是"用字符串 id 去查注册表"的地方（语言、编解码器、枚举键），
> 查不到时几乎都是静默降级而非报错，必须实测而不是看代码觉得对。
> 这条与交接文档铁律 12（`BaseEnum` 的 `value` 字段）、铁律 13（判空口径）同族。

## 5. 其它

### 5.1 起止时间选择器自动补当天起止

带 `show-time` 的选择器，选完日期后时间部分默认取"当前时刻"，
用户还得再点进时间列改成 `00:00:00` / `23:59:59`，一个查询条件要点四五次。

新增 `src/constants/date-time-const.js` 提供三个默认值，覆盖 9 个文件共 15 处
（范围选择器 5 处 + 起止配对 10 处）。

实测（真实点击，全程只点日期、不碰时间列）：

| | 结果 |
|---|---|
| 开始时间 | `2026-08-02 00:00:00` |
| 结束时间 | `2026-08-02 23:59:59` |
| 范围 | `["2026-08-02 00:00:00", "2026-08-05 23:59:59"]` |

> ⚠️ **刻意没动"时间点"语义的字段**：开奖时间、计划开奖时间、公告发布时间、达标时间、
> 创建时间、更新时间、代码生成器的前后端日期。把它们默认成 0 点会改变业务含义
> （比如开奖时间变成午夜），需要逐个确认后再定。

### 5.2 monaco 路由改名连带数据库

路由 `/monaco-editor` → `/code-editor`。

> ⚠️ **这条路由是数据库里的正式菜单**（`t_menu` id=301「在线编辑器」），不是只能手敲 URL 的 demo 页。
> 只改前端会让该菜单 404，因此 `t_menu.sql` 种子数据同步修改，并新增增量脚本
> `sql-update-log/v3.51.0.sql` 供已有库升级。
>
> 附带查明：该菜单的 `component` 字段（`/business/monaco-editor/JsonEditor.vue`）**本就是失效值** ——
> `buildRoutes` 按 `../views/<component>` 解析，而该组件在 `src/components` 下，从来没被解析到过；
> 页面实际由 `routers.js` 的静态路由提供。

## 7. 方法论：这轮验证是怎么做的

产物体积类改动的共同风险是**改错了不会报错**（空白图表、没有高亮、编辑器不可用），
所以每一项都做了浏览器实测，而不是"构建通过就算过"：

1. **临时挂 dev 路由**把待验组件挂上（交接文档 §0 记载的既有做法），验证后删除；
   路由守卫需临时放行，同样验证后还原。
2. **用可量化的信号断言**，不靠肉眼：
   - 图表 → canvas 像素采样（非透明点数、色彩数）
   - 高亮 → 统计语法 token 的 class 种类数（切换语言前后对比）
   - 双向绑定 → 模拟输入后读绑定值
   - 只读 → 模拟输入后确认文本未变
   - 时间选择器 → 真实点击日期格后读 `v-model` 的值
3. **区分"没报错"和"真的对"**：例如只读态下 `contenteditable` 仍为 `true`，
   光看属性会误判成没生效，实际是输入被拦截了——必须用行为验证。

> 另一个反复踩到的坑（后端同源）：**验证前先确认跑的是不是刚构建出来的那份**。
> Windows 上残留的 JVM / dev server 会锁住产物，让 `clean` 静默失败、跑的还是旧包。
> 详见后端白皮书 §4.4。
