## 0. 一句话

**一个积分营销平台：运营在后台配任务、抽奖、彩票、积分商城，会员在 C 端完成任务、参与活动、兑换商品；奖品经风控与预算审批后发到会员的资产里。**
功能主体已经完整，内测、演示、小范围试运营够用；**正式对外运营还差真实外部通道、合规与运维三块**（§5）。

## 1. 系统全貌

### 1.1 三个进程 + 两个前端

```
                 ┌─ app.taozicn.me ──► web(nginx) ──► solvela-app（C 端网关 :1025）──► solvela-app-biz（C 端业务 :1026）
Cloudflare 隧道 ─┤                                          只连 Redis                    会员 / 营销 / 奖品 / 资产 / 商城
                 └─ admin.taozicn.me ─► web(nginx) ──► solvela-admin（管理端 :1024，独占定时任务）
                                                            └──► MySQL 8.4 / Redis 8 / MinIO
```

| 进程 | 职责 | 关键点 |
|---|---|---|
| `solvela-app`（网关） | C 端唯一入口：鉴权、设备身份、滑块、二次验证、给前端拼数据 | **没有数据库驱动**。经 `@HttpExchange` 契约调 app-biz，将来拆服务时调用方不改 |
| `solvela-app-biz` | C 端业务：会员、营销、奖品、资产、商城 | 不对外发布端口；**不跑定时任务** |
| `solvela-admin` | 管理端 + **全部定时任务** | 多一个进程跑调度 = 发奖与结算重复执行 |
| `solvela-app-web` | C 端 H5（Vue 3 + Pinia） | 手机优先，底部四个入口：首页 / 商城 / 任务 / 我的 |
| `solvela-admin-web` | 管理端（Vue 3 + Ant Design Vue） | 前面有 nginx Basic Auth（+ 建议的 Cloudflare Access） |

**将来要拆出去的是资产域**（`solvela-ledger`：钱包、券、实物履约）。跨域聚合一律放在网关（例：`/me/summary`），不在 app-biz 里跨域打结。

### 1.2 后端模块

| 分类 | 模块 |
|---|---|
| 进程壳 | `solvela-admin` / `solvela-app` / `solvela-app-biz` |
| 业务域 | `solvela-marketing`（任务 / 抽奖 / 彩票 / 活动）· `solvela-prize`（奖品）· `solvela-risk`（提案 / 预算 / 审批）· `solvela-ledger`（资产：钱包 / 券 / 实物履约）· `solvela-mall`（积分商城）· `solvela-member`（会员 / 等级 / 设备 / 登录）· `solvela-notification`（站内信 / 公告）· `solvela-external`（外部通道：话费充值）· `solvela-scriptengine`（脚本编排） |
| 跨进程契约 | `solvela-member-api` / `solvela-marketing-api` / `solvela-contract` / `solvela-model` |
| 底座 | `solvela-auth` · `solvela-base-*`（core / data / file / mail / mq / redis / web） |

技术栈：Java 25 + Spring Boot 4.1 · MyBatis-Plus · MySQL 8.4（85 张表）· Redis 8 · MinIO · 自研 SonicExcel（替换 POI / EasyExcel）· 自研数据库抢占式调度。

### 2.2 奖品派发链路

`抽奖 / 彩票 / 任务 → 奖品事件 → 提案（风控 + 预算硬扣减 + 审批）→ 资产到账`，端到端对过账。
已注册的派发策略：积分、余额、优惠券、实物、彩票号码、标记（MARKER）。跨服务对账与重投、卡单扫描都有定时任务兜底。

### 2.3 会员与资产

| 能力 | 现状 |
|---|---|
| 资产 | 积分 / 余额钱包，流水可追溯 |
| 优惠券 | 发放 → 券包 → 下单试算 → 锁定 → 核销 / 释放的完整闭环；过期收口、卡单释放、即将过期提醒 |
| 实物履约 | 三段式：中奖 / 兑换建单 → **用户补填地址** → 运营发货；收件信息加密存储、脱敏展示 |
| 会员等级 | 考核周期制，成长值独立于积分；保级缓冲期；等级权益（商城专享、等级价、抽奖额度）真正落到钱上 |
| 消息 | 站内信 + 公告（含强制确认公告），通知偏好 |

### 2.4 积分商城

商品 / 规格 / 分类、等级价与单品覆盖价、专享商品、兑换（纯积分；积分 + 现金见 §5）、订单、收藏、地址簿、最便宜在售规格价展示。

### 2.5 账号安全

完整说明见 `docs/架构/账号安全全景图鉴.md`。已上线即拦截的：

- 滑块验证码（发邮箱 / 短信验证码、密码登录之前）
- 登录限频：IP 维度（含对不存在账号的尝试）+ 账号锁 + 设备维度计数与观察档
- 观察档二次验证凭票发码（不知道密码拿不到票）
- 新设备登录提醒（邮件 + 站内信，认注册设备）
- Web 端凭证放 HttpOnly cookie，跨站写请求一律拒绝
- 防点击劫持、HSTS、隐藏路径（`/.env` 等）404
- PII 加密存储，密码 Argon2id

### 2.6 C 端

底部四入口：首页（轮播 + 精选商品 + 活动）/ 商城 / 任务 / 我的。
「我的」页一屏看全：等级徽章、消息铃铛、资产卡、券包 / 彩票 / 奖品 / 收藏四个数（`/me/summary`，COUNT 口径）、奖品按待填地址 / 待发货 / 已发货分组、常用服务宫格。

## 5. 离正式运营还差什么（按优先级）

### 5.1 必须先定的

1. **彩票合规。** 国内对彩票类内容有资质要求，决定彩票功能能否对外、App 能否上架。其余工作的优先级依赖这一条。
2. **短信服务商。** 未接（生产配置 `allow-missing-sms-vendor: true`）。手机号注册 / 登录走不通，二次验证只有邮箱一个因子。

### 5.2 运维底线

3. **数据库自动备份。** 目前没有定时备份。
4. **日志持久化 + 基础监控告警。** nginx 访问日志只在容器 stdout，重建即丢；没有错误率 / 可用性告警。
5. **管理端访问控制确认**：Cloudflare Access 策略（`deploy/README.md` 第 4 步）、管理员密码已从基线初始值改掉。

### 5.3 真实外部通道（看业务是否需要）

6. **支付网关。** 全仓没有支付网关代码，`solvela.mall.pay.transport` 只有 `FAKE` 一个可用值，默认 `DISABLED`。只做纯积分兑换可以不接。
7. **话费充值运营商。** `solvela.external.recharge.transport` 只有 `FAKE`；生产环境配 `FAKE` 会启动失败，配 `REAL` 也会（后端没有运营商对接代码）。

### 5.4 安全收尾

8. §4 三个开关切到拦截。
9. 已知小缝：下线单台设备不撤该设备信任；无滑动续期（30 天必须重登）；管理端无 CSP；邮箱登录失败提示仍是「手机号或密码错误」。
10. 迁移代码（`/auth/session/adopt`、`token-storage.ts`、`device-storage.ts`）**2026-10-26 之后删除**。

### 5.5 技术债（不阻塞上线）

| 项 | 说明 |
|---|---|
| `AsyncConfig` 线程池队列无界 | 没设 `queueCapacity`，拒绝策略从不触发，积压全在堆里；抽奖 / 彩票派奖走的就是它（任务事件已另建有界池隔离） |
| 任务 `rule_script` 第三层未执行 | 前两层表达不了的规则只能改 Java。建议真遇上一两次再做 |
| 改角色权限不清权限缓存 | 基座问题，改完需登出重登。修法明确，未动（与上游升级冲突） |
| 基座 `addProposal` 权限串错误 | 16 个基座 Controller，受限角色「新增」按钮失效。同上，未动 |
| `/me/summary` 串行调下游 | 7 次调用，几十毫秒。真成瓶颈再并行（需重绑请求上下文） |
| 存量压测脏数据 | 见交接文档 §5 第 9 条，可选清理 |

### 5.6 下一阶段（产品层面）

- **App 端。** 推荐 Capacitor（Android / iOS）+ ArkWeb 薄壳（鸿蒙）复用 H5；必须补推送、设备绑定（Keychain / Keystore）、生物识别等原生能力，否则过不了 App Store 4.2。后端登录接口已支持非 cookie 模式。
- **旧号不可用时的换绑通道**：多弱证据叠加 + 冷静期，方案见本会话讨论（尚未成文）。
